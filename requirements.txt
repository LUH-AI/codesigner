# HPO core, pinned to a branch again — deliberately, and this is the second
# time, so the reason matters.
#
# No release carries the acquisition weight layer: `add_prior`,
# `TabulatedPrior`, `DECAY_SHAPES`. A prior stated on the acquisition figure
# reaches the search through those, so on a released SMAC the figure still draws
# but `SMACOptimizer._apply_priors` logs that it cannot apply anything and the
# run proceeds unweighted — which is a working install with a silently inert
# feature, and is why this is a pin rather than an optional extra.
#
# The branch does not descend from the 2.4.1 tag; it forked at v2.4.0. It does
# carry both of that release's fixes independently — the scikit-learn 1.9
# random-forest import, and copying forbidden clauses in
# `create_uniform_configspace_copy` — so there is nothing to gain by moving to
# the release, and the weight layer to lose. It installs as 2.4.0 because the
# version string on the branch was never bumped.
#
# pyrfr is an optional extra and is not pulled in, so this needs no swig and no
# compiler; every other requirement here resolves to a wheel.
